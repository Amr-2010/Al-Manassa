# Al-Manassa: PostgreSQL and AI setup

## Deployment state
The Blazor web application now reads courses and dashboard counts from PostgreSQL. No demo course list is hardcoded in Razor. If the database is unavailable the UI shows an error rather than fabricated statistics.

## Database
1. Provision a **dedicated** PostgreSQL database for Al-Manassa. Do not reuse the Xerox database.
2. Run database/002_courses_and_seed.sql against that database once. This creates courses and curriculum_suggestions and inserts three idempotent demo records.
3. Set DATABASE_URL on the Al-Manassa Render web service to the dedicated database connection string. Never commit it.
4. The web service uses Npgsql. Schema is not auto-created on startup.

## Real AI
- Set OPENAI_API_KEY as a secret environment variable on the web service.
- Set AI_ADMIN_TOKEN to a long random secret. This is a temporary backend-only access gate until ASP.NET Identity and role-based admin login are implemented.
- Optional OPENAI_MODEL (default gpt-4.1-mini).
- POST /api/admin/ai/curriculum with X-Admin-Token header and JSON {"topic":"Cybersecurity","level":"Beginner","language":"Arabic","durationWeeks":8}.
- The server calls the OpenAI API and stores the returned JSON as PendingReview in PostgreSQL. No AI request is made if secrets are missing. Never send the token or OpenAI key from public browser JavaScript.
- The dashboard deliberately does not expose the admin AI action until secure authentication is built.

The currently linked Render deployment must be rebuilt to run these changes. This repository change has not been verified by a successful .NET build. MAUI packages are not generated by Render.
